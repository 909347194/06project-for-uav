# 发布与安装

项目有 **3 个互相独立的包**，可按需单独发布、单独安装：

| 包 | pip 名 | wheel 文件 | 版本 | 作用 | 依赖 |
|---|---|---|---|---|---|
| ta1 | `uav-task-allocation1` | `uav_task_allocation1-0.2.0-py3-none-any.whl` | 0.2.0 | 任务分配：谁飞、什么顺序、回哪个巢 | numpy / pillow / pyshp |
| pp1 | `uav-path-planning1` | `uav_path_planning1-0.4.0-py3-none-any.whl` | 0.4.0 | 路径规划：一条航段怎么飞（航迹 + 时长 + 净空） | numpy / scipy / shapely / pillow / pyshp |
| scene_io | `uav-scene-io` | `uav_scene_io-0.2.0-py3-none-any.whl` | 0.2.0 | 数据适配：世界 / 任务包 → 库输入 | 零运行时依赖（仅标准库） |

三者互不 import（scene_io 的桥接是懒加载，用到才 import），所以**可以给全套，也可以只给某一个**——只用分配就只装 ta1，只用规划就只装 pp1。一句话口径：三个 wheel 各自独立，按需组合。

- 仓库均为 public：`https://github.com/909347194/06project-for-uav`
- 导入名分别是 `task_allocation1` / `path_planning1` / `scene_io`（与 pip 名不同，别写错）
- 支持的 Python：3.11 / 3.12（三个包都要求 `>=3.11,<3.13`）

## 发布（你）：3 步

| 步 | 做什么 | 命令 / 位置 |
|---|---|---|
| ① 提交改动 | 先 commit，让 Release 对应一个干净版本 | `git add -A && git commit -m "release: v0.4.0"` |
| ② 构建三个 wheel | 产物在各自的 `dist/` 下 | 仓库根执行 `uv build task_allocation1 && uv build path_planning1 && uv build scene_io` |
| ③ 建 Release | 网页打开仓库 → Releases → Draft a new release → tag 填 `v0.4.0` → 把三个 `.whl` 全拖进附件 → Publish | `github.com/909347194/06project-for-uav/releases` |

- 版本号来自各自的 `pyproject.toml`（ta1 是 0.2.0、pp1 是 0.4.0、scene_io 是 0.2.0），**三者独立演进、不必相等**。
- 每个 `dist/` 里还有 `.tar.gz` 源码包，上传 wheel 就够，源码包可不传。
- 网页上传无需安装 `gh`；一次发布用网页最省事。

## 安装（对方）

三个 wheel 都在同一个 Release、URL 只有文件名不同。按需选一条：

**全套（分配 + 规划 + 数据适配）**——三条 URL 一次装完，pp1 带 `[nlp]` 自动装 casadi：

```bash
pip install \
  "uav-task-allocation1 @ https://github.com/909347194/06project-for-uav/releases/download/v0.4.0/uav_task_allocation1-0.2.0-py3-none-any.whl" \
  "uav-path-planning1[nlp] @ https://github.com/909347194/06project-for-uav/releases/download/v0.4.0/uav_path_planning1-0.4.0-py3-none-any.whl" \
  "uav-scene-io @ https://github.com/909347194/06project-for-uav/releases/download/v0.4.0/uav_scene_io-0.2.0-py3-none-any.whl"
```

**只要分配（ta1）**：

```bash
pip install "uav-task-allocation1 @ https://github.com/909347194/06project-for-uav/releases/download/v0.4.0/uav_task_allocation1-0.2.0-py3-none-any.whl"
```

**只要规划（pp1）**：

```bash
pip install "uav-path-planning1[nlp] @ https://github.com/909347194/06project-for-uav/releases/download/v0.4.0/uav_path_planning1-0.4.0-py3-none-any.whl"
```

**只要数据适配（scene_io）**：

```bash
pip install "uav-scene-io @ https://github.com/909347194/06project-for-uav/releases/download/v0.4.0/uav_scene_io-0.2.0-py3-none-any.whl"
```

安装注意：

- **`[nlp]` 只作用于 pp1**：它让 pip 连 casadi 一起装（约 60 MB），`duration_s` / 轨迹才有值；去掉则 pp1 只有几何层，`trajectory` 恒为 `None`。已实测带 `[nlp]` 时 pip 会自动解析并下载 casadi。ta1 没有这个选项。
- **`scene_io` 的 `[ta1]` / `[pp1]` 可选依赖不要在这里用**：它们指向 PyPI 上并不存在的包名，直接装 Release wheel 时会失败。想用 `to_ta1_request()` / `to_pp1_world_kwargs()` 这些桥接，就按"全套"那样把对应算法 wheel 一起装。
- **引号别省**：`[nlp]` 在 bash/zsh 里是通配符，会被 shell 展开。
- **pip 要 19+**（2019 年后），`@ URL` 直接引用语法才可用。
- 依赖（numpy / scipy / shapely 等）由 pip 从 PyPI 自动拉取，对方需联网。

## 发新版

三个包版本独立：哪个改了就升哪个的 `pyproject.toml` 版本号 → 重新 `uv build` 那个包 → 建新 Release（如 `v0.4.1`）并把新 wheel 传上去 → 把安装命令里对应的 tag 和文件名改掉。旧版本 URL 仍有效，可按版本复现。注意 Release 的 tag 是整次发布的标记（便于归档），不要求等于某个包的版本号。

> 无法访问 GitHub 的场合，把需要的 `.whl` 直接发给对方，用 `pip install xxx.whl` 本地安装；pp1 若要轨迹再补 `pip install casadi`。优点是不依赖网络，缺点是要手动传文件、URL 不再固定。
