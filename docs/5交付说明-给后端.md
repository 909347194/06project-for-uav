## 2. 后端接入必读（5 条）

1. **高度口径只有一条：绝对 `z`。** 拉萨地面 ~3650 m，"离地 40 m" 就是 `z_abs ≈ 3690`，
   **不要传 40**。pp1 收到绝对 z 后自己按 DEM 派生真高，你也不要再减一次地面。
2. **起降不进 pp1。** ta1 的 tour 是 `巢 → t… → 巢`，但巢在地面。交给 pp1 的必须是
   **空中航段**（每个航路点都按巡航真高抬到绝对 z）；垂直起降段自己拆。见教程 §7。
3. **代理不是交付值。** ta1 的 `path_m` / `est_cost` 只用于**排序**；
   交付值永远是 pp1 的 `length_m` / `duration_s` / `min_clearance_m`。
4. **`duration_s` 可能是 `None`。** 没装 `casadi`（`pip install "path_planning1[nlp]"`）
   或 NLP 降级时 `trajectory is None`，此时 `status=ok` 但**不能当已验证时间可行性**——
   标 `DEGRADED`，只给折线。
5. **缓存键是三个指纹**：`dataset_digest`（数据内容）+ `params_hash`（参数与场身份）
   + `world_id`。任一变了结果不可比，缓存必须失效。`params_hash` 一定要进你的结果序列化，
   否则分不清 startup 场版与 on_demand 现算版两套 SDF 口径。

## 3. ⚠️ 已知问题（**接之前必须知道，别踩**）

### 3.1 配置面有 22 个"死旋钮"（P1）

ta1 的配置面比实际消费的宽。下面这些字段**写进配置不会产生任何效果**，别指望它们：

| 所属 | 无效字段 |
|---|---|
| `ConstraintConfig` | `require_all_tasks` `require_no_idle` `sequence` `sync` `w_misc` `w_range` `w_endurance` `w_window` `w_seq` `w_sync` `w_nest_capacity` `w_nest_availability` `w_end_nest_reachability` |
| `ProblemConfig` | `allow_unassigned` `allow_idle_uav` `late_reward_decay_seconds` `coverage_audit` |
| `SolverConfig` | `coverage_first` `demand_serve_margin` `polish_eps` |
| `Task` | `sequence_group` `sequence_order` |

**真正在判的约束只有 7 个**：`duplicate_task` / `range` / `endurance` / `time_window` /
`nest_capacity` / `nest_availability` / `end_nest_reachability`（+ 恒开的同巢约束）。

> 后果：**任务先后序（"先侦察后投送"）和多机同步目前没实现。**
> 需要就在上层拆成多次调用，或排期让我们实现。代码里已逐项标注"预留、不生效"。

### 3.2 参与机上限 `K ≤ N-1` 会让两架机跑三个任务（P1，待决策）

`task_allocation1/core/participating.py` 强制参与机数 ≤ 任务数 − 1。
所以 **5 架机 5 个任务时会被裁成 4 架参与**，"每架机直飞一个任务"这种解结构
**不在搜索空间里**。另外 `ModelType.OVERLOADED` / `BALANCED`（除 N=1）两条编码分支
在主链路永不触发，也没有全程测试。

**这不是 bug 报告，是需要拍板的设计问题**：是放开到 `min(len(uavs), n_tasks)`，
还是写进"已知限制"？影响解质量，建议联调时用真实数据实测对比。

### 3.3 DEM 的 GeoTIFF 栅格类型未校验（P1，条件性）

`path_planning1/core/dem_terrain.py` 不读 `GTRasterTypeGeoKey`(34735)。
若 DEM 是 `PixelIsArea`（GeoTIFF 默认），所有地面采样会**整体偏半像元**
（30 m DEM ≈ 15–20 m），楼底 / 真高 / 禁飞区 AGL 换算全跟着偏。

**接入前请核对自己那份 DEM**：`gdalinfo dem.tif | grep -i raster`。
是 `PixelIsPoint` 就没事；是 `PixelIsArea` 先跟我们说，需要补一个 −0.5 像元修正。

### 3.4 示例数据是合成的（重要）

`data/worlds/lasa_chengguan/` 的**建筑轮廓与 DEM 都是程序生成的示意数据**
（坐标基准、`frame_hash`、`dataset_digest`、`z_abs` 口径都是真的）。
`docs/examples/run_lasa_demo.py` 的输出数字**只证明流程通**，不代表拉萨的真实可飞性。

**换成实际数据前不要用它的结论**，按教程 §11 的清单换数据。

### 3.5 其它（P2，不影响主链路）

- `min_clearance_m` 报 **30.0 表示"至少 30 m"**（量程上限 `CLEARANCE_SEARCH_RADIUS_M`），
  不是精确值——跨请求比较时注意。
- 覆盖门禁（`gate_stats`）是**一阶判据**（只看航程能不能装下），不考虑时间窗/续航，
  所以赶不上时间窗的任务也会被判 `voluntary_skip` 并计罚。
- `docs/ta1_full_config.example.json` 里包含 3.1 的无效字段（保留是为了配置形状稳定）。
- 完整审查清单（P1×5 / P2×24）另有报告，含每条的行号与修法；已修 7 条，其余待排期。

## 5. 服务壳该做什么（归后端）

本仓是**纯计算库**：不碰 HTTP / 缓存 / 进程池 / 落库 / 超时。你要自己包一层：

| 事项 | 建议 |
|---|---|
| 生命周期 | `create_context()` **进程启动时一次**，不要每请求建一次（建场 17 s / 255 MB） |
| 多进程 | `ctx.save_field(目录)` → 其它进程 `create_context(field_artifact=目录)`，mmap 共享，启动 0.18 s |
| 并行 | 单航段可并行（8 路左右），pp1 内部无全局状态 |
| 超时 | 单段 0.6–3 s（首段含 CasADi 建模 3 s）；建场 17 s 量级 |
| 异常 | `pp1.FieldContractError` = **部署事故**（产物过期/契约漂移），告警 + 拒绝就绪，**别映射成 400** |
| 入参错误 | `ValueError` = 调用方 bug（NaN 坐标、零间距、机型推重比 < 1），归 4xx |
| 业务失败 | `plan.failure_code`（9 种）→ 结果码，见 `docs/2` §失败码映射 |
| 缓存 | 键 = `world_id` + `dataset_digest` + `params_hash` |
